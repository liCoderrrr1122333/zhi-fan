#智能体运行架构

本文只讲当前代码已经实现的部分。项目动机和研发过程见[项目故事与设计思考](项目故事与设计思考.md)。

## 代码分层

```text
app/agent/loop.py                循环、工具执行、边界控制和运行轨迹
app/agent/tools/                  策略召回、课程信息、案例、人工接管
app/llm/                          模型接口、火山引擎适配、离线规则桩
app/services/chat_service.py      会话、规则拼接、纠偏和策略固化
app/services/playbook_service.py  策略样本与语义召回
app/services/review_service.py    工单与指标
app/services/settings_service.py  业务规则与策略总纲
app/db.py                         本地数据表
```

## 一轮请求怎样运行

1. 对话服务把业务规则、策略总纲、会话历史和用户问题交给循环引擎。
2. 模型看到当前消息和可用工具，返回“调用工具”或“结束回答”的结构化决定。
3.循环引擎执行工具，把结果追加回当前消息。工具报错也会变成结果。
4. 模型带着新结果继续判断，直到回答完成，或触发步数、超时边界。
5. 系统返回回复和轨迹，记录命中与转人工等指标。

`AgentLoop` 不负责识别“价格类问题”或“就业类问题”。模型在工具清单和上下文里自己决定下一步，代码负责执行和守住边界。

## 策略怎样进入下一次请求

一条样本由客户问法、建议回复和判断理由组成。它可以来自主动录入、工单补充或确认后的纠偏。服务时按当前问题召回最相关的几条；总纲归纳读取全量样本。

优先级是：**人工维护的业务规则 > 策略总纲 > 召回的具体样本**。纠偏重答只影响当前会话；确认固化后才写入长期策略库，并更新总纲。

## 可观察性与边界

运行轨迹记录每轮给模型的上下文、模型决定、工具输入输出和最终回复。这样能分清是没有查到资料、查到了却没用，还是业务规则本身写得不清楚。

当前已实现最大步数、超时、错误回填和人工接管。长会话压缩、自动评测、策略版本回滚、租户隔离和高风险动作审批仍未实现。
